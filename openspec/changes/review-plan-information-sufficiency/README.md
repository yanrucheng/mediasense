### Agent 建议：按决定的影响判断充分性

这部分是待讨论的验收解释，不是新增固定流程。

| 真实问题 | 对组织的影响 | 建议判断 |
| --- | --- | --- |
| 西餐聚餐、烧味午餐、牛排晚餐的身份 | 用户可能按餐厅找回；城市与餐厅还影响章节含义 | 优先利用可读招牌、菜单、源上下文或用户知识补足；不因已有泛称就默认调查结束 |
| 康得思品酒班与丽晶晚餐 | 同一餐前段还是另一酒店活动，会改变活动解释及分组 | 需要调查这项关系；后续更正只作用于相关范围。时间相邻或同一天不足以认定同一活动 |
| 已有招牌／菜单与上下文相互支持的餐厅 | 再次提问未必改变组织 | 可由 Agent 作有来源的判断，遇到实质反证再质疑，不逐店强制确认 |
| 餐厅身份仍不可得，但某一天的一次用餐可信 | 可以确定活动，不能确定店名 | 可提出较粗候选，明确未知项、范围及它损失的检索线索；不能把沉默记成用户接受 |

提交完整候选的依据应是：已明确拟解决的找回目的；重要分组、命名和例外有适用于该范围的支持；已知的实质冲突已经处理，或通过有依据的较粗表达／显式处置保留；所有来源有完整唯一去向；用户能够看见影响接受的剩余不确定性。充分性相对于所提组织的精细度，不是保证未来不会出现新信息，也不是声称所有未知事实均已查清。

尚有会改变关键组织决定、且未处理的信息缺口时，应继续调查或展示方向，不将其包装成已具备最终确认条件的完整组织。提出一个诚实的较粗候选，不等于用户已经接受这种精细度；接受仍属于其后对确切候选的审阅。

### 建议的可验证改进

- 优先用本次反例检验已有 Skill 的实际执行，再决定是否需要改写说明；不只再增加一句“主动调查”。如需改写，在现有调查、Profile 检查与提交候选段落中解释“粗称是否掩盖实质缺口”和“未知是否仍影响拟议决定”，不新增固定问答程序。
- 既有交互验收已经包含独立合成推演，并非只有关键词检查；它证明了那些代表性路径，没有证明本次真实旅行中的信息优先级选择。后续验收应给 Agent 可得证据与真实找回目的，在不事先告诉它“哪些餐厅待问”的情况下，观察第一版提交前的调查与判断。
- 正例同时覆盖“有足够依据直接推进”“关键背景不足时主动调查”“用户不记得或未回复时诚实保留”“后续纠正改变活动边界”。反例包括按时间直接认定 F、G 同场、用菜单选项推出实际点餐、将每一家店都强制提问，以及只在 notes 写未定却声称问题已解决。
- 单独评价首版、用户推动后的修订与确切候选接受；不能以最终改对抹去首次过早提交，也不能把正确修订计作原版通过。保留地图证据缺失的场景，不等待第 1—3 包修复。
- 最终审阅要呈现重要判断的来源类别、实际适用范围、剩余未知及其检索影响；这些内容进入既有 Candidate 说明。HTML 自动生成与页面实现属于第 6 包。

### 复核通过后的目标与完成标准

用户转交的[独立验收](../../../eval/sessions/260912-2333-hk-run-acceptance/report.md)确认：第 4 包判断准确，尚无修复完成证据；菜名研究深度不应成为落实已有职责的前置条件。

本包目标是让 Plan Agent 在请求完整候选确认前，自行识别和处理会实质影响找回、分组、命名或处置的信息缺口。已有证据足够时推进，关键支持不足时选择调查或交互，无法取得时形成有依据的较粗表达或显式未决处置。剩余未知及影响须可审阅；不要求保证所有事实已穷尽或未来不会更正。

方案应围绕以下完成证据收敛：

1. 实际使用的 Plan Skill 保留并清楚传达这些判断职责；必要修改落在既有 Skill，方法、交互形式和顺序保持开放。
2. 行为验证只向 Agent 提供可得证据与用户的找回目的，不预先点名重要缺口或正确答案；观察它能否主动识别影响、选择下一步并形成可审阅决定。
3. 对照场景证明信息充分时无需多问、未知时不造答案、更正时限定范围并更新候选；首次提交、后续修订与最终接受分别评价。只核对指导文字或 Tool 结构校验不构成完成。
4. 验证保留地点缺失等现实限制，不等待第 1—3 包修复；验证过程不修改已封存 Result 或替用户确认业务 Plan。

餐厅与活动身份优先补足；具体菜名在有助找回且证据可靠时使用，本次额外网上研究按后续用户目标评价。是否进一步提高同类素材的默认菜名研究深度保持可选讨论，不阻挡上述方案收敛。当前不需要重新讨论主动调查职责、固定阈值／轮数、工作说明或最终确认机制。
