## MODIFIED Requirements

### Requirement: PreCheck remains local-first with one bounded online exception
The Skill SHALL keep external work disabled by default and use the confirmed media-aware compressed coordinate scope through the existing Geo Tool boundary. It SHALL distinguish policy-disabled evidence from confirmation waiting and Human refusal, without inventing a skip bypass or acquiring new authority itself.

#### Scenario: Default local run
- **WHEN** the online exception is disabled
- **THEN** no remote model, online map, upload or billable request is authorized and truthful unrequested location does not alone block Plan

#### Scenario: Frozen reverse-geocode set needs confirmation
- **WHEN** the Tool pauses with a frozen Geo disclosure
- **THEN** the Agent explains coordinates, exact pending queries, Provider policy and cost bounds, then uses the trusted client confirmation workflow

#### Scenario: User skips reverse geocoding
- **WHEN** the Human explicitly declines the pending authorized proposal
- **THEN** the Agent reports the contract's cancelled Run without publication, not a fictitious successful skip Result; dismissing the client control instead leaves the Run paused

### Requirement: Result axes govern handoff and escalation
The Skill SHALL interpret coverage and readiness independently, rely on the Tool's verified read boundary for integrity, and hand Plan only one exact immutable Result with material limitations. It SHALL NOT require every photo to have location or retry terminal Geo failures through an Agent loop.

#### Scenario: Result is partial but plan-ready
- **WHEN** trusted Read reports partial coverage and plan_ready
- **THEN** the Agent may offer that exact Result with qualifications without searching for an integrity constant

#### Scenario: Result is blocked
- **WHEN** Read reports blocked readiness for a real unmet prerequisite
- **THEN** the Agent explains that reason and asks for needed direction without resuming or cancelling an immutable Result

#### Scenario: Result is ready for Plan
- **WHEN** the Human proceeds with plan_ready Result, including one with location gaps
- **THEN** the Agent passes its exact ref and uses public Read for later facts

## ADDED Requirements

### Requirement: Skill examples use the compact PreCheck contract
The Skill SHALL use flat action and dataset_ref inputs, distinguish progress from accounting, accepted controls from reached states, and terminal localized issues from whole Run failure. It SHALL retain scope and effect confirmation duties without copying Tool implementation algorithms into Skill instructions.

#### Scenario: Status looks inactive
- **WHEN** status reports no_recent_progress or suspected_stalled
- **THEN** the Agent follows the reported reason and allowed controls rather than inferring failure from one timestamp

#### Scenario: Geo failed after bounded retries
- **WHEN** Tool returns a terminal failed component
- **THEN** the Agent describes missing information, does not resubmit automatically, and continues toward a qualified Result when other prerequisites hold
