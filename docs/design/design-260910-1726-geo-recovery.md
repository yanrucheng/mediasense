# Geo 业务阻塞诊断与恢复方案

本文保留已核对的诊断，并据用户确认的业务目标收敛下一阶段执行计划。目标与停止边界已明确，用户已授权开发。**0.10.0 已实现并通过合成故障、旧版账本形状和隔离安装入口验证；本次未恢复真实业务或调用地图服务**。实际证据和认证边界见既有 capability-ledger 的 0.10.0 交付小节。当前唯一合约权威仍为 [docs/spec/contract/](../spec/contract/index.md)；迁移分类与完成证据只维护在[既有 capability-ledger](../eval/eval-260823-1918-ai-album-migration-baseline/eval-260823-1918B-capability-ledger.md)。

## 结论与证据边界

此次网络故障的具体原因仍未知；导致整份 PreCheck 无出口的原因已经明确：当前契约将可能已发送的查询归为 indeterminate，并要求整批停止；原请求重放只返回 journal 结果，PreCheck 遇到已有 indeterminate Work 又直接停止，公开接口没有可以执行“核对、接受缺口或授权另一次尝试”的操作。

用户最终确认的目标是：**Geo为素材提供适合后续理解、分组与命名的地址和附近地点证据；先根据目标地点选择服务，再根据运行网络判断能否使用。** 内地地点优先高德等适合内地地址/POI的服务，尽量避免先用Google再回退。海外地点需要当地适用的服务；如果运行网络无法访问、且没有能满足需求的替代服务，保留进度并暂停，由用户决定提供Proxy、调整网络或其它方式。运行机器在内地不等于素材地点在内地；已授权或能连通都不证明服务适用。

此前“Google不通就转高德、失败就记缺口继续”的笼统推荐撤回。AI Album的连接超时回退是有价值的机制证据，只有候选服务对目标地点和所需组件适用时才能采用。服务持续不可用是业务前提缺失，不能自动降为单点缺信息后生成完成Result。这一目标约束下面所有路由、重试、恢复、交付和验收。

应保留这种对未知效果的诚实记录，但把两个问题分开：**上一次发生了什么**，以及**是否允许再做一次、或者就此结束获取**。地图读取通常可重复，但重复可能再次计费、消耗配额、披露坐标；可重复性必须由具体 operation/provider profile 证明，不能由 GET/POST、异常名称或“只读”一词替代。

本轮源码 HEAD 为 `6037952`，起始工作区干净。已确认 installed 0.9.0 的 `geo.py`、Geo service/tool/journal、PreCheck geocode、runtime composition/config 与该源码相同。只读核对了用户指定的业务 surface、确切 Dataset 的 SQLite 记录和 Host 网络环境；没有恢复、取消或重跑业务 Run，没有打开 fixture 媒体，也没有调用地图或模型。

### 故障原因仍有哪些未知

当前只保留 `error_code=transient` 和 `Provider completion is unknown after transport failure.`，没有阶段、异常类型、errno、TLS验证代码、elapsed或provider response id。无法区分连接超时、响应超时、代理、TLS或其它传输异常，也无法据此证明Google服务故障。

在该仍存活的业务MCP进程中，允许名单检查没有发现HTTP/HTTPS/ALL proxy及CA覆盖变量；父Agent有NO_PROXY而子Host没有。当前macOS HTTP/HTTPS/SOCKS/PAC enable flags均为0。这是**环境传递未完整保留的实际证据**，不是本次故障的因果证明：父进程没有配置代理地址，透明VPN/TUN或故障时的系统状态未验证；此前同一nearby endpoint的42次成功也不支持“Google从来不可达”。当前密钥启动脚本只设置两家API key，证明密钥接通不能证明网络环境接通。

### 已复现的额外实现缺陷

安装版的合成序列：`地址成功 → 附近503（安全可重试）→ 整组再次执行 → 地址未知`。结果是地址component变成indeterminate且candidates为空，先前地址成功仅在attempt中留下状态。原因是service在indeterminate分支 `selected.pop(operation, None)`；复合重试又重新读取已成功组件。

这是**违背已有“成功组件保留”承诺的实现缺陷**，不需要新授权语义才能修复。应让已获得候选及其原provenance保持可读，同时把新一次失败/未知另记；优先只补欠缺组件。AMap可以一次响应共同提供两组件，不强制拆成两个HTTP；额外共同读取也必须计数，不能覆盖先前成功。

另一个受控探针确认，DNS错误被识别为0请求/可安全重试；连接timeout、读取timeout、TLS证书错误都被当前transport归为同一不可安全重试消息。这只能证明分类分辨率不足；测试构造的原因不能倒推本次真实异常。

这里有两种关联：传输分类和网络配置影响“哪些故障会出现、是否具备重试依据”；恢复/终结契约影响“任何一次故障能把多少已完成工作挡住”。前者改好不能消除响应丢失，后者改好也不能修通错误代理或证书。两方向必须共用同一尝试事实与预算，不能分别堆叠独立重试循环。

## 已确认目标下的执行行为

### 先判服务适用性，再判可达性

路由的输入是目标坐标、datum、已证明的地域依据及需要的组件；网络位置、语言、代理状态与端点健康是另一组输入。候选路线必须同时满足：对该地点/组件适用、在授权范围、当前可用或值得有限尝试。允许列表不是适用性证明。

| 场景 | 默认行为 | 必须避免的行为 |
| --- | --- | --- |
| 内地地点、高德可用 | 优先高德；若它满足所需组件，本项不调用Google | 为了探测国家先发一遍Google；把运行机器所在地当素材地域 |
| 内地地点、首选服务暂时失败 | 有限重试；只考虑已授权且对该地域/组件适用的备用路线；没有适合服务则报告等待条件 | 一律切Google；用可连通但不合适的结果掩盖获取能力不足 |
| 海外地点、适合服务可达 | 使用适合当地地址/POI的服务；保留实际provider、datum、语言和范围 | 因为人在内地或用了中文就选内地API |
| 海外地点、适合服务持续不可达、没有有效替代 | 停止该Run新增外部请求，保存成功组件和未完成项，公开可执行的网络/配置恢复条件；等待用户选择Proxy、网络或其它方式 | 自动改用缺乏有效覆盖的高德；逐点反复连接超时；自动批量记missing后宣称完成 |
| 一个组件成功、另一个偶发故障 | 保留成功组件，只补欠缺部分；有限重试/适用回退后根据证据判定局部失败或服务不可用 | 丢掉成功地址；因nearby失败推断reverse endpoint也不可用 |
| 个别地点有效查询后无结果、或已证明为地点级失败 | 保留no_result/failed与原因，继续其它项；按现有Result不变量决定能否完成 | 把服务/网络整体不可用也归为地点级失败 |
| 地域/覆盖依据不充分 | 标明不确定范围；优先使用已保存的可靠来源或可追溯的本地判定；无法形成可靠路由且影响执行时一次请求明确地域/服务约束 | 用GCJ02转换适用范围、语言、文件名、粗略矩形或上一坐标的国家替代地域判断 |

“内地优先”不宣称一个服务对每个地点都绝对更准，也不允许过滤掉与预期不符的真实响应。港澳等独立服务覆盖边界需单独验证，不能由含China/CN的文本一刀切。当前香港实验也不能仅因地图不可达就切成内地路线。

当前生产路由只有固定Google→AMap顺序，没有可复用的精确离线地域边界。实施先核对已有保留地域证据和可用的本地边界资源，选取来源/许可可核对、版本可追溯的最小判定方法；混合地域按坐标分别处理，不能默认一个Dataset只有一个国家。尚无可靠依据的坐标必须走显式不确定分支，不能以此为由删掉自动路由能力或强迫用户逐张选服务。如果必须下载新的边界资产或引入新的许可/数据接收方，先带具体资源、用途和替代方案讨论，不自动下载。

### 区分局部缺口与获取前提缺失

有限重试耗尽是一个执行事实，本身不证明“只有这个地点没有信息”。Geo应根据结构化的错误阶段、服务商返回及范围区分：

- **地点级结果**：有效响应的no_result、可明确归属该坐标/请求的终结失败，可局部交代并继续；适合服务仍可用是局部处理的前提。
- **短暂传输/服务错误**：在有限次数、时间和原授权范围内处理；发送证明与是否允许重复独立判断。若恢复成功，原未知尝试仍保留。
- **路线或服务不可用**：连接持续失败、凭据失效、账户配额、代理/TLS配置问题，且无适用替代，保存进度后暂停。单次timeout不自动断言网络被封；有限尝试后仍无适合路线时，也不能逐地点继续碰运气或自动关闭全批缺口。
- **效果/预算证据不全**：所有者尚在执行、账本损坏、历史发送上界无法界定，阻止新增请求，给出实际可执行的处置范围，不能要求用户证明不可回查的远端事实。

暂停使用现有Run状态与结构化reason/confirmation，不增加假“运行中”或另一个生命周期。停止新增请求时，已在途的请求仍需完成或如实保留未知；status读取不发探测。若用户确实选择放弃某范围的Geo获取，必须通过公开Tool明确记录其范围与后果；这不是服务不可达时的默认出口。

### 需要用户介入的时点

本轮无需用户决定重试次数、HTTP异常分类或每个地点选哪家服务。用户已明确“内地优先适用的内地服务；海外适用服务不可达且无有效替代就暂停”。工程选择在这些目标下完成，合约补充是实施步骤，不再提出抽象的两项政策问卷。

运行时才需要用户决定：适用海外服务不可达时采用什么网络/Proxy；新增未授权服务商或数据接收方；扩大累计请求/费用上限；无法保守核定剩余额度；或用户明确选择改变/放弃某范围的获取要求。现有日志不能证明本批已经需要Proxy，不能预先要求提供，更不能自动配置代理或降低TLS校验。

### 执行与计费判断

| 当前事实 | 允许的动作 | 预算/记录要求 |
| --- | --- | --- |
| 已证明未发出（DNS、连接拒绝、可靠的连接阶段超时） | 有限重试或转适用且已授权的备用服务；没有有效路线时暂停 | 记本地attempt，远端请求0；本地尝试次数/时间仍消耗，不能无限循环 |
| 已收到可重试响应（如受控429/503） | 尊重有效Retry-After与deadline，重试欠缺组件；账户/服务级持续失败不能当作地点级缺口 | 原请求照计，退避/回退共用同一预算；不足以继续则暂停或按地点级已知结果终结 |
| 已发送或可能已发送，响应未知 | 仅在具体查询可重复、有效策略/权限明确、无仍在执行的所有者、预算可保守核算时另记尝试；对本次旧批次通过公开恢复绑定新策略 | 原unknown不改写，不确定请求保守占额，billable未知继续为null；成功重试不能抹去旧未知 |
| 认证/参数/TLS信任/代理错误 | 区分服务级与地点级原因；可用且适用的授权路线可以接替，否则保存进度并等待具体修复 | 不自动换代理、凭据、接收方或关闭TLS验证；系统性故障只提示一次，不对每个坐标重复 |
| 地点级失败已终结 | 按已确认目标保留缺口，继续其他项 | 缺失字段按事实标failed/missing，不将未请求或网络故障标no_result |
| 适用服务持续不可达或整批预算耗尽 | 暂停并交代受影响范围、已完成量、剩余义务和可执行下一步 | 未决条件不满足完成/Plan-ready；用户明确放弃范围是另一项公开决定，不能默认替代修复 |

组件获取结束与一次传输的原始结果不是同一状态。局部终结的Observation可为failed，basis解释未取得候选、终结依据、原未知与有效策略；它不声称远端执行失败。网络/服务整体前提仍缺失时，不能借这种投影宣布Run完成。

### 最小公开恢复路径

复用现有Geo Tool、PreCheck Run、confirmation、Work和journal。需要明确的读取/处置语义，但不预先强制新增两个inspect/recover操作、独立GeoRun或通用恢复服务；正式API形状在第一步确定，完成条件是以下路径闭合：

1. `status`/现有诊断能显示确切阻塞范围、已保留组件、原未知效果、累计额度和真正可执行的下一步。读取/重复读取无外部请求；没有可靠发送证明时不能只提示“自行核对后恢复”。
2. 用户配置网络/Proxy或其它条件后，经现有Run `resume`承载的有类型恢复决定执行。Tool校验Run、待处置身份、有效配置、适用路线与剩余额度，Host仅对实质新增/变化的授权内容取得可信确认。先已授权的小范围查询承担恢复验证，不另加隐藏地图探测；再次失败保留原因返回暂停，不能靠反复普通resume耗尽整批。
3. Geo内部恢复请求显式关联原操作与具体欠缺组件，沿用同一累计预算。原request_id及原有效输入重放保留原结果、0新增HTTP；新恢复决定有幂等身份，重复决定不重发，竞态或过时决定命中原结果或拒绝。PreCheck无需向Agent泄露私有Work ID。
4. 若用户明确放弃某范围，通过同一公开决定记录范围、未取得信息和对后续任务的影响；它是用户选择，不是海外服务不可达时自动采用的默认。cancel继续表示停止Run而不伪造完整Result。
5. PreCheck幂等接收Geo的后继证据，只补欠缺组件，保留旧Work/Result原字节。网络路径或重试策略变化不能使114条有效历史结果、42条本批成功及第43项地址全部失效；若观测profile本身改变使某项不再适用，应解释确切失效范围。

本地状态核对不承诺能从Google/AMap回查一次丢失响应。当前没有可用的provider请求回查身份；修复网络、接受缺口或再次查询均不能将原unknown标成已核实。只有能绑定确切attempt的可信外部证据才可追加核对结论。

### 一份跨恢复链的预算与证据

Geo journal持久化根请求完整授权范围、有效retry/transport profile、每次HTTP发出前的额度占用、发送阶段、响应或未知、关联恢复记录和完成组件。每次新请求在同一事务核对当前处置版本、执行所有者和累计额度，再取得发送资格；网络调用后更新自身attempt，不持锁等待网络。

- 当前示例总上限仍为486。已有86条中未知一条不能减回0，也不能在恢复时重新获得486次。在适用路线恢复后，若仅补附近一次并成功、其后11点均用Google成功，新增为`1+11×2=23`，累计109。只有明确的地点级终结依据或用户选择放弃该附近信息，且后11项的服务可用时，新增22、累计108才是合法例子；它不是海外服务不可达时的自动降级路径。两种例子都保留1次原未知、金额未知；示例成功次数不是预先保证。
- 后继请求只分配剩余额度，可缩小；增加累计上限、provider、坐标集合、附近范围、数据类或改变代理接收边界都须新的明确授权。原逻辑坐标集合去重后仍是54，HTTP尝试/重试数独立累计，不把重试称为新增媒体覆盖。
- 每次自动执行周期可先采用现有至多3次、1/3秒退避、120秒窗口作为保守起点，具体失败分类与适用回退优先级由工程验证决定；适用服务已经持续不可达时应及时暂停，不要求耗满额度。累计尝试数与请求数不在resume/换对象时归零。用户确切解决网络条件后的一次显式恢复可以获分配新的有界尝试周期，仍受原累计请求上限约束；不能把“每周期3次”误当成用户修复网络后永远不能恢复，也不能以重复同一决定无限重开周期。
- 自动窗口含退避和provider耗时；暂停/超期不在普通replay时重新起表。新恢复周期的身份、有效条件与分配额度持久化，相同恢复决定重放不能重置窗口。原窗口早已过期的本批，先完成公开恢复处置后才能启动有界新窗口；本计划不启动它。
- 已证明未发送可释放对应远端请求占用；未知发送保留占用。旧版整批admit后崩溃而没有逐HTTP记录时，不能假设后半批没发：先按可证明的保守上界占用，无法核定则不给自动续费权限，向用户披露已有上界与另行追加的范围。
- 完整授权与处置留在journal中；Run确认字段可以表示当前交互，不能再成为唯一历史授权存储。PreCheck和Geo各自SQLite不共享一次事务，需要通过既有请求身份实现“先journal提交、再幂等投影”；任一点崩溃都不能重复发请求或漏记成本。

## 最终执行顺序与评价标准

按“适用服务→可达执行→效果/证据保存→公开恢复→Result交付”推进。业务目标、授权边界和验收场景固定；实现库、算法、表结构和内部顺序开放。用户已授权开发。以下是完整交付门槛，源码组件通过不等于所有步骤或安装入口已经通过。

| 步骤 | 工作产出 | 通过标准 |
| --- | --- | --- |
| 1. 固定地域、故障范围与完成规则 | 在唯一当前合约中补齐内地/海外/混合范围的适用路线、局部缺口与网络阻塞、重复尝试及公开恢复的必要字段；保留主体模型 | 正反例能明确判定：内地优先高德；海外合适服务不可达且无有效替代则暂停；孤立有效无结果可继续；仅剩unknown费用不等于还在执行，未解决网络前提不算完成。不给客户端两套并行协议 |
| 2. 实现服务适用性与冻结路线 | 补可追溯的目标地域判定及provider/组件适用条件，按坐标独立决定候选路线；已有合理缓存不重查 | 内地健康路径Google HTTP数=0；海外不因高德可连通就采用其不适用结果；混合/乱序批次结果范围正确；港澳、边界邻近、未知datum/地域不能误入内地默认。地域判断不依赖Google首次在线成功，不新发探测；资源来源/许可明确 |
| 3. 修复传输分类、配置传递与有限执行 | 接通实际Host的代理/NO_PROXY/CA/timeout设置及结构化错误；重试、适用回退、限速与暂停由一个机制拥有；修复已成功候选丢失 | 连不上、响应丢失、HTTP429/503、参数/鉴权错误分别有可证明的分类；不明原因旧记录仍不明；“地址成功→附近失败→重试故障”地址不丢。Google海外路线持续失败无替代时在有限次数/时间内暂停，不逐地点超时；合法局部故障不扩成永久全Run阻塞 |
| 4. 持久化逐请求事实和累计预算 | 扩展现有Geo journal记录原披露、逐HTTP预留/结果、恢复关联与成功组件；完成旧版可证明状态迁移及PreCheck幂等投影 | 原请求/重复恢复0新增HTTP；双客户端不能双发；在admit/发送/接收/投影各点崩溃，未知不变0、成功不丢、累计不超界。换request_id或Host重启不重获486次额度。旧数据无法证明的效果保持保守未知；无关store/artifact不机械升版 |
| 5. 接通暂停与公开恢复 | 用已有status/confirmation/resume提供清晰的“缺哪个适用服务、需要何种条件、恢复哪些项”路径；网络修复后只继续欠缺部分 | 用户能通过正常入口完成“海外服务不可达→暂停→提供合适网络配置→明确恢复”，无需SQL/删缓存；条件未修复返回具体阻塞，status不做探测，重复恢复不重复发送，取消不生成假Result。新代理/接收方或预算扩大须有可信授权 |
| 6. 验证组件交付、复用与完成判断 | Geo→Work→Result→Read→Plan验证成功组件、孤立失败、已处置未知、未决网络条件和费用；新证据有真实来源 | 合成114复用＋42成功＋1附近未知＋11未查形状中，正常恢复新增23次/累计109，原86及unknown费用保留；成功缓存与第43地址不重做。未解决海外服务不可达时仍暂停、无新的完成Result；服务可用下的地点级失败能显式交代并进入后续Plan。旧Result哈希不变 |
| 7. 隔离发行与真实入口验收 | 构建匹配合约的新发布候选，用安装wheel的CLI/MCP、正式composition和npx项目Skill/lock验证；记录原台账 | 下列安装场景全部通过，源码/wheel/schema/Skill和锁一致，CLI原可选依赖保留，无全局Skill。交付包和证据后停下；实际环境切换、Proxy设置及本次业务Run恢复按明确授权另行安排，不终止当前主Agent |

步骤2的地域资源选择和步骤3的网络传输选择是有明确验收门槛的工程工作，不是现在必须让用户拍板的业务方案。若现有资源无法在成本/许可边界内满足要求，报告具体缺口而不是静默用近似判定宣布通过。

### 必须通过的安装场景

| 场景 | 观测值与拒绝条件 |
| --- | --- |
| 内地地点＋Google不可达＋高德正常 | 高德直接成功，Google尝试0；没有“先用Google判国家”的隐含开销 |
| 海外地点＋Google不可达＋高德可连通但不适用 | 不向不适用高德发送；有限尝试后Run暂停，提示具体网络条件；已有成果留存，无完成Result，不继续对余下地点重复打同一路线 |
| 上一场景经用户配置Proxy后恢复 | 只有明确resume启动有限恢复；实际Host使用所选配置，仅补未完成组件，原scope和累计额度不扩大；再次失败能回到同一可解释停点 |
| 海外正常服务中的单点无结果/明确地点级失败 | 该点如实missing/failed，后续点继续；不能用这个正例接受整个海外服务都不可达的降级 |
| 内地/海外混合、港澳及边界不确定 | 各项按适用性分别路由；处理顺序、运行机器位置、语言不改变地域事实；不确定项有独立依据或明确待解决项，不伪造内地结果 |
| 已有成功地址、附近503/断流/响应丢失 | 成功地址与provenance保留；只补欠缺部分；每次HTTP含重试真实计数，原未知费用保留；两endpoint的健康状态不混淆 |
| 同一恢复重复、并发、超预算、确认过时及进程崩溃 | 不产生重复或超界HTTP；成功数据与授权未丢；剩余额度不可证明时拒绝新增效果，普通状态读取无副作用 |
| 两家适用性/可达性均不足或系统配置错误 | 有明确暂停原因及公共下一步；不能将整批未取到数据当作no_result封存，也不能通过改状态绕过阻塞 |

底层验证使用合成坐标、临时Dataset和虚拟时钟；不运行模型、不用真实数据源从零验收。安装验证必须启动最终wheel自带的`mediasense mcp`，保持生产composition与真实HTTP adapter。外部服务替换为隔离loopback proxy/受控TLS服务，用假key模拟连接失败、延迟、丢响应和服务错误，禁止外部网络fallback；测试CA仅对测试子进程有效。不能用提前写好Geo返回的fake provider冒充实际安装恢复链路。

## 主要工程风险、取舍与停点

- **账本原子性与跨进程并发是最高风险。** 若授权、预算占用与请求归属不同步，进程崩溃或新request_id会重复计费。接受请求数上界有时较保守，优先于低估未知；不实现无限自动“核对”。
- **成功缓存与恢复身份不能互相破坏。** 全局profile变化可能使大量成功缓存失效；恢复选择与累计成本必须独立于可复用观测内容。已有成功不得因新失败被覆盖；旧Result不就地改写。
- **分类分辨率不能大于底层证据。** 如果urllib无法证明发送阶段，应替换或扩充内部transport以保留结构化事实；不能通过解析异常message宣称未发送。增强诊断仍不保证能追溯此次原因。
- **地域判断与服务覆盖是前置风险。** 当前缺少可靠的离线地域判定；粗框会把港澳/邻境等送错路线，先调用Google又会违背内地优先目标。服务适用证据须独立于连通状态；资源/许可选择须验证。海外服务不可达且无适用替代时暂停，不能以不合适的高德结果冒充完成。
- **局部容错不能掩盖业务前提缺失。** 有效服务中的孤立失败按有限规则结束；海外适用服务不可达、系统性配置/配额故障时必须暂停。错误不能靠失败率阈值自动转成全批缺口。用户决定网络修复或明确放弃范围，Tool决定有限重试等实现参数；不对每个坐标重复问同一问题。
- **当前版本不可无声改行为。** 公共恢复语义落地需要版本化发布、schema和项目Skill同版；切新Host前确认无在途所有者，并避免旧Host继续写迁移后的journal。不终止当前主Agent或其它服务。

不需要改变Source Item/Evidence/Observation主体模型、Geo采集阈值或Plan命名策略；也不需要旧项目runtime依赖。目标与停止边界已由用户确认，现有证据足以形成执行计划；继续猜测此次网络根因不会替代地域适用性、网络暂停及累计预算的验收。若今后取得真实exception/代理日志或provider侧账单，可补强根因与成本判断；若发现某operation不可重复、剩余成本不可界定或新接收方超出授权，则重新审阅对应恢复资格。
