# Plan 预览生命周期：自动交付与资源回收

## 目的、授权与交接状态

Plan 保存后，其可视化结果自然可用。Human 和 Agent 的正常工作中不增加生成 HTML、启动服务、续租、关闭或清理的步骤。Agent 继续解释方案、提供或打开 Tool 返回的页面；只在异常时使用已有诊断和恢复入口。没有使用时，运行时自行释放展示资源。

用户已认可保留现有动态页面、自动管理生命周期的方向，并明确补充“每次一更改完，这个东西就在那”，展示基础设施对 Human 和 Agent 均应尽可能无感。用户最初授权设计轮次作出专业工程判断、完成可直接交接的设计，**仅做设计**。随后于 2026-09-15 明确授权开发和验证；当前实施证据见文末。`active` 表示设计已收敛，不能单凭该状态声称实现或发布完成。

最初设计交接不修改代码、测试实现、当前合约或发布资源。本次开发已按后续授权实施并将交付承诺同步到[当前 Plan Work 合约](../spec/contract/plan-work/index.md)，仍不操作真实 Plan、冻结或 Apply，不切换日常安装；当前公开行为以该合约为准。已完成的[整理方案界面](design-260915-1244-plan-preview-simplification.md)保持现有标题、折叠、网格和信息范围。

预览是可重建的展示能力，不增加持久业务对象、公共 Tool、独立 Skill 或服务管理产品。Work、Result、Frozen Plan 继续拥有其原有权威；缓存与进程是否存在不参与业务完成、确认或冻结的判断。

## 已确定的工程选择

| 议题 | 本轮定案 |
| --- | --- |
| 交付方式 | 复用普通 `plan.work` 成功调用后的 `view_delivery`；不改成 Agent 单独生成静态报告 |
| 常规操作 | create、update、seal 自动交付；inspect 默认含 view，显式 state-only inspect 仍不启动服务 |
| 服务范围 | 同一用户、所选 data home、确切构建复用一个按需启动的 loopback 进程；不新增守护进程或系统登录服务 |
| 不同方案 | `(workspace binding, dataset_ref, work_ref)` 独立路由；同一 Work 的更新复用该运行进程中的路由 |
| 版本 | current URI 用于继续讨论，revision URI 用于精确审阅；回收不放宽过期拒绝 |
| 地址持久性 | 路由在本次服务进程内有效；不保证跨退出／重启继续可用，不新增固定端口、常驻唤醒器、URL 重定向注册表或自定义协议 |
| 重缓存 | 按 Work 回收整个展示上下文；闲置超时和全局容量共同约束，轻量路由不引用这些对象 |
| 服务退出 | 无实际使用满 72 小时且无在途业务读取时自动退出；后台版本轮询不续期 |
| 重新使用 | 下一次普通 Plan 交付内部启动服务并返回新入口；Agent 不额外管理服务 |
| 活动判定 | 内容请求和实际页面交互续期；不依靠 unload，不把可见标签页或固定心跳当持续使用 |
| 持久清理 | 只清理运行时自有临时文件和有界诊断；不生成每次展示的历史 HTML，不清理任何权威资料或已有 thumbnail |
| 异常入口 | 沿用 `views status/stop`、state-only inspect、inspect with view／相同请求重放；不新增正常工作步骤 |

这里固定目的和可观察保证。下文的超时、对象数量、内部方法名是首版工程选择，可在有验收证据时调整，不是 Plan 业务参数，也不要求用户设置。

## 范围与兼容性

本轮解决自动生命周期、内存缓存持有、路由隔离、并发退出、受控诊断及临时文件保留。没有增加编辑、搜索、证据面板、导出历史、远程托管或业务目录分类。预览继续读取已有准备图片；不得重新准备媒体、回退原图或调用模型来恢复展示。

沿用当前合约的 Zero BC 选择，不增加新旧公开路由、别名或双写。此次不需要改变 `plan.work` 的 action、请求／响应字段、Work 格式、确认上下文、Frozen Plan 编码或数据迁移。浏览器与服务使用同一构建的内部协议，诊断 CLI 可以增加明确的运行信息。已有业务数据和封存字节保留。

旧版没有空闲退出机制，不能靠新代码自动使已运行的旧进程具备此能力。未来安装切换按[单一安装 runbook](../../readme/installation.md#upgrade-and-rollback)停止已识别的旧构建服务；禁止凭进程名称批量杀进程。本次开发验证也不执行该切换。

## 现有实现与缺口

| 现有位置 | 已有能力 | 本轮缺口 |
| --- | --- | --- |
| [PlanWorkTool.handle](../../src/mediasense/plan/work.py) | 先保存业务回执，再独立交付 view；可 state-only 读取 | 保留该关系，不增加 Agent 的 start/render/stop 调用 |
| [plan_views.py](../../src/mediasense/runtime/plan_views.py) | 确切 build、启动锁、健康核验、后台进程、显式 stop | 没有自动闲置退出；ensure 与 bind 之间存在退出竞争窗口 |
| [_view_server.py](../../src/mediasense/runtime/_view_server.py) | 每个 Work 独立 token；只读页面、当前版本、分页与图片 | routes 强持有完整 PlanView；没有容量、活动或回收策略 |
| [PlanView](../../src/mediasense/plan/view.py) | 按 revision/state 重建分析、成员和计数 | 包含分析、resolver、成员、Plan Tool 和闭包中的 PreCheck Reader，不能只清外层 members |
| [SQLitePlanStore](../../src/mediasense/plan/_sqlite.py) | 权威 Work 快照 | current 读取仍可反序列化整份组织；需存储层的最小绑定读取 |
| [页面脚本](../../src/mediasense/_resources/plan-view/app.js) | 按需加载图片，4 秒版本检查，过期不拼接 | 缓存图上的展开和滚动无网络请求；轮询不应唤回重缓存或延长进程寿命 |

此前约 443 MiB 的服务 RSS 是一次已浏览数据的观测值，不是最低需求、峰值上限或经过归因的内存基准。已有 Read 的封存文件大小预算也不是 Python 对象或进程 RSS 的字节上限。本设计分别约束可达重对象、在途工作和进程寿命，不用这两个数字伪装物理内存保证。

## 责任与状态归属

| 所有者 | 负责 | 不获得的权限 |
| --- | --- | --- |
| Human | 方案与重大业务取舍的确认 | 无需掌握服务命令或清理预览 |
| Agent / Plan Skill | 正常保存、解释、交付当前／精确入口；异常时选用诊断 | 不写 HTML、不维护展示数据、不承担常规资源回收 |
| Plan Work Tool | 保存和业务失败、原始回执、精确确认；触发 view_delivery | 展示失败不能回滚保存，重试交付不能重复语义写入 |
| 现有 Runtime | 进程、路由、活动、缓存容量、在途请求、退出与诊断文件 | 无权修改 Work、Result、Frozen Plan、缩略图或 Apply 状态 |
| PlanView / PreCheck Read | 从权威数据构造投影，校验绑定与图片 | 不因缓存缺失而换版本、换图、跳过真实性检查 |
| 浏览器 | 展开状态、可见性、临时交互通知和局部反馈 | 活动不是 Human 接受，不持久化业务或开启本地可执行文件 |

运行时只需三类内存事实：轻量路由、可选重上下文、在途请求与时间戳。它们属于现有 Runtime，不作为公共实体、独立注册表或持久会话文件。`accepting`／`draining` 只表达请求接入闸门是否已关闭；不新增 Plan 的 queued、paused 等状态。

```mermaid
flowchart LR
    A[普通 Plan 保存或含 view 的读取] --> B[内部确保服务并绑定 Work]
    B --> C[返回当前入口和精确版本入口]
    C --> D[浏览分组和已有预览]
    D --> E[数据读取闲置后释放重上下文]
    E -->|服务仍在，继续读取| D
    E --> F[整机内该服务无使用且无在途读取]
    F --> G[闲置退出，回收进程内存]
    G -->|下一次普通 Plan 交付| B
```

## 自动交付与失败边界

1. `PlanWorkTool.handle` 的成功业务回执不变。每次 create/update/seal，包括 notes-only 或 same-value save，照常尝试交付该回执版本的 view。失败写入不触发新的业务内容展示；读取不创建 revision。
2. Runtime 将“找到健康服务、必要时启动、绑定 Work”作为一次内部交付动作；Agent 不先查询服务状态，也不发独立的启动命令。
3. 继续以实际投影检查决定 `ready/degraded/unavailable/superseded`。没有计算过的核心内容不能因为分配了 token 就声称 ready；不在本轮把投影改成无执行所有者的后台任务。
4. 保存已提交而进程不可用，返回原成功回执与真实的 view 限制。意外 renderer 异常仍沿现有 `operation_failed`／`committed_receipt` 路径，不能被归入正常闲置或 queued。
5. 对已明确收到 `retiring` 或连接拒绝的本次交付，Runtime 在原交付的 60 秒总期限内只重试一次 ensure/bind。重试的是无业务写入的绑定，始终使用原回执 Work/revision。超时但旧请求可能仍在执行时，不立即启动第二次昂贵绑定。
6. 若期间出现新版，返回 superseded 与当前入口，不把旧回执升级成新版。正常 view inspect 或 identical replay 可再次观察当前交付状态；不要求保存一条“恢复展示”的工作说明。

服务启动仍受现有 15 秒启动上限约束，且包含在总交付期限中。缺权限、启动失败、磁盘不可用或投影本身超过期限，保留具体错误；自动生命周期不能保证这些基础设施故障不可见。

一个正常使用例子（为说明计时，假定请求都在所列时间点完成）：

| 距本次开始 | 行为 | 可观察结果 |
| --- | --- | --- |
| 0 秒 | Agent 正常保存 Work A / r1 | Tool 自动返回 A 的 current/revision 入口，无额外启动调用 |
| 60 秒 | Human 展开 A 并加载图片 | 数据读取时间和使用时间均更新 |
| 185 秒前 | 此后没有新数据请求，仅版本轮询 | A 的重上下文释放；路由和浏览器图片保留 |
| 240 秒 | Human 滚动已加载内容 | 活动通知更新使用时间，不重新载入 Result 图 |
| 845 秒前 | 此后无人操作，持续只有 current 轮询 | 服务自动退出；所有进程内存回收 |
| 900 秒 | Agent 正常保存 A / r2 或读取 view | 自动交付新进程入口；读取本身不创建版本，保存按原规则创建版本 |

若 Work B 持续有有效使用，服务可以继续运行，但 A 的重上下文仍按自己的数据读取时间释放。B 不改变 A 的路径、版本或确认。

## 路由、版本与多方案

内部路由键继续由明确的工作区定位与 Dataset/Work 身份组成。工作区物理绑定、manifest Dataset 和 Work 的 Result 需核对；不得按显示名称合并，不得把大小写不一致的路径字符串简单 lower-case 后当作证据定位。冷重建保留原绑定语义，路径复用或介质替换不能把旧句柄导向别的数据。

```text
同一服务 origin
  /v/<随机入口 A>                 Work A 的当前入口
  /v/<随机入口 A>?revision=<r1>   Work A 的精确版本
  /v/<随机入口 B>                 Work B 的当前入口
```

- 不同 Dataset 或不同 Work 必须有不同 token；同名方案、复制到另一工作区的 Dataset、相同 logical_root 不能共用路由。token 是只读访问句柄，不是确认凭证。
- 同一进程中的同一绑定复用 token，包括重缓存清空后重建和同一 Work 保存新版。轻量路由不随一次缓存淘汰而删除；已加载页面不会因为别的 Work 被访问而失去地址。
- 精确 URI、分页游标和图片读取仍绑定原 revision。冷重建时先从存储最小读取判断 revision，再做昂贵构造；旧请求直接 409，不用新版重建后冒充旧版。
- 当前入口的重新加载可以读取新版；已打开页面只提示新版，不自动替换其内容。冻结只改变 Work 状态时仍核对 state/publication，不依赖 revision 单项缓存。
- 服务退出清除全部内存路由；新进程使用新 origin/token。旧 origin 不承诺有服务返回过期页，可能直接连接失败。不得说旧链接会自动唤醒。正常 Plan 调用会返回新入口，版本与确认规则不变。
- 已冻结 Work 不因展示闲置而删除，旧 Work 的入口不会转向后来创建的 Work。展示退出也不意味着整案审阅或 Human 确认。

为避免单个长期活跃进程无限保存入口，轻量路由首版上限为 **256 个 Work 绑定**。达到上限且是新绑定时返回 view 不可用及容量原因，不淘汰或重定向已有入口；同一绑定仍可使用。正常闲置退出会清空该表。这个极端容量故障可由 Agent 诊断／停止当前服务处理，不成为普通操作要求，也不限制持久 Work 的数量。

## 首版参数与计时

以下值放在现有 Runtime 内部配置值或常量中，并允许测试注入。首版不增加用户 TOML、环境变量或启动选项。

| 参数 | 首版值 | 依据与含义 |
| --- | --- | --- |
| 重上下文闲置时间 | 3,600 秒（1 小时） | 从最后一次实际投影／图片读取完成计；保留近期上下文以减少停读后的昂贵重建 |
| 全局重上下文容量 | 2 个 | 含构造中、在用和保留的 Work 上下文，不随浏览器标签页数增长 |
| 重计算并发 | 每 Work 1 个，全进程至多 2 个 | 从构造到响应资源释放；同一 Work 请求复用同一个上下文 |
| 等待重上下文名额 | 最多 5 秒，等待者最多 16 个 | 有实际 Condition／信号量支撑的同步等待；超出后明确 503，不伪造队列任务 |
| 服务闲置时间 | 259,200 秒（72 小时） | 从最后一次有效交付、内容请求或真实交互计；在途请求阻止退出 |
| 回收检查间隔 | 5 秒 | 到期后在进程可运行且无竞争时，最多一个检查周期开始回收 |
| 浏览器活动上报节流 | 最多每 30 秒一次，含末次延迟发送 | 一个交互序列只更新一次近期时间，不记录事件明细 |
| 版本检查 | 可见页沿用 4 秒；隐藏页暂停 | 不续期、不构造重缓存，恢复可见时立即检查一次 |
| 显式 stop 排空期限 | 5 秒 | 停止接入后尽量完成读取；逾期中断只读请求并退出，不无限等待 |
| 日志保留 | 单文件 1 MiB，最多 1 个轮转备份 | 每个运行构建最多约 2 MiB；普通轮询和图片请求不逐条记录 |
| 已停止构建的诊断保留 | 7 天，下次普通交付顺带清理 | 不为了准点删除临时文件另启后台清理服务 |

时间使用 `time.monotonic()`；不使用页面时间或墙钟调整延长服务。系统休眠期间不能承诺执行清理；恢复调度后重新判定。休眠是否计入单调时间随平台而定，因此最迟在恢复后一个完整闲置周期内退出，不为此增加原生时钟适配器。测试覆盖墙钟前后调整、休眠恢复和重新进入页面，不能依靠时间倒退永久续期。

## 两种时间与活动判定

**数据读取时间**决定重上下文能否被丢弃；**使用时间**决定进程是否退出。用两个字段表达，不混成一个 last_access。用户在浏览已经加载的图时，不必继续占有 Result 图；但近期实际交互应避免服务恰好退出。

| 信号 | 延长进程寿命 | 延长重缓存寿命 | 备注 |
| --- | --- | --- | --- |
| 接受一个可信 Runtime bind，包括保存后交付或 view inspect | 是 | 仅实际执行投影时 | 失败投影仍保持其真实失败，不伪造用户接受 |
| 已绑定页面的文档导航、overview/page/evidence/asset 请求 | 是 | 仅实际需要重上下文的请求 | 先验证必要的 revision；合法请求以完成时间更新，在途计数覆盖发送响应 |
| 已绑定、同版本页面的真实点击、键盘、触摸、滚动通知 | 是 | 否 | 只维护短小时间戳 |
| current 版本检查、服务 health/status | 否 | 否 | 必须使用最小绑定读取，不能反序列化完整 Candidate |
| CSS/JS 请求、失败重试定时器、仅保持页面可见 | 否 | 否 | 不能把系统自己的活动误当用户使用 |
| 非法 token、跨源请求、旧 revision 的通知、未授权请求 | 否 | 否 | 被拒绝的请求不能永久续期 |

服务刚启动有 72 小时初始宽限；有效 bind 或文档打开建立最近使用时间。请求执行中使用 pin；完成后在 `finally` 中撤销 pin，并在适用时更新时钟。预期局部资源错误也结束一个真实请求，不把错误遗留成永久 pin。

**持续静止阅读满 72 小时也允许退出。** 首版不猜测人是否还在看，不做无限可见性心跳。已经加载的 DOM 和图片仍在浏览器中；需要再读取而服务已退出时显示简短恢复提示。此取舍避免遗忘的前台标签页永远占用后台进程，并沿用用户认可的“再次打开通常交给 Agent”。

### 浏览器活动通知

在现有页面适配器内增加私有 `POST /v/<token>/activity`，请求只带页面固定的 `revision`。这是展示资源的内存记账，不是公共 Tool action，更不是 HTTP Plan 写入、确认或 Apply。

- 仅在页面可见且收到真实用户输入时发出，监听点击／指针按下、键盘、触摸或滚动。移动鼠标、合成事件、初始化程序展开、当前版本轮询不能续期；不保存事件类型、坐标、按键、人员身份或历史。
- 第一次即时发送；连续操作使用 30 秒节流及一次末次发送。隐藏时停止轮询并取消无必要的定时发送，重新可见先检查版本；一次重新进入可见页可以通知近期使用，不启动永久心跳。
- 请求必须通过现有 loopback/Host/token 检查，并要求浏览器同源 Origin、JSON content type 和最多 256 bytes 的合法请求体；形状为 `{"revision":"<本页 revision>"}`，拒绝多余字段。不得使用 control secret；传入其他 Work 或任意路径一律无效。普通 browser POST 的作用严格限于活动，不把现有 control 路由开放给网页。
- 服务从存储最小读取当前 revision/state，匹配后更新时间；过期返回现有 409 语义，不更新时间，不改变页面版本。成功响应与 current 相同，为 `revision`、`state`、`idle_remaining_seconds`，后者是向上取整且不小于零的相对秒数，无业务数据写入。
- 活动失败不阻断已经加载的分组折叠，也不排队无限重试。实际继续请求内容前检查连接／版本，失败时按下一节反馈。

## 重上下文回收与内存边界

### 轻量路由不保留重对象

把现有 `routes[token] = PlanView(...)` 分成一条轻量路由记录和可选上下文引用。轻量部分仅保留工作区绑定、Dataset/Work/Result 定位、必要锁与计数、时间；不保存 Candidate 内容、Source Item 集合、图片字节、读取图或捕获它们的闭包。

重上下文仍由现有 `PlanView`、它的 `PlanWorkTool`、renderer 和该展示专用的 PreCheck Reader 组成。淘汰时一起解除强引用，包括 `analysis`、`resolver`、成员索引和 Reader 的 Result 图。**不清空同一 Dataset 中其他 Tool/Run 持有的 Reader，不修改公共 PreCheck Read 接口，不用 Python GC 代替生命周期设计。** Request 和日志不得永久保留异常 traceback 或上下文对象。

### 取得、占用与释放

1. 先核对 token 与最小 Work/revision 绑定。命中同一重上下文则复用；同一 Work 不能由并发请求构造两份。
2. 对空路由，在全局容量内预留名额，再构造；构造中的名额也计入上限。需要名额时选择无 pin 的最久未读上下文，整份释放后再构造新的。
3. 全部名额均有 pin，或同一 Work 已有重请求时，进入同一个有界等待池；超时或等待人数满返回 503 `view_resource_busy` 及 `Retry-After: 1`。最多保留 16 个等待重操作的请求，不创建后台任务。活动／current／health／stop 不占重名额，避免资源忙时诊断也排在昂贵读取之后。
4. 请求期间不淘汰其上下文。pin 从 admission 到序列化、图片响应发送或失败释放完成；不能在 Python 仍持有大对象时提前宣称已释放名额。
5. 满 1 小时没有重读取且无 pin，检查器释放该上下文。页面活动和 current 请求不阻止回收。`current` 需走存储层新增的最小只读方法，只取 Work/result/revision/state/必要 publication 标识，不通过 `PlanView._load()`；该方法以只读连接访问已存在的数据库，不调用建库／迁移初始化，不读取 notes/preferences/Candidate 正文。
6. revision/state 变化时，待旧读取结束再丢弃旧上下文；新读取不能复用旧分析。旧请求末尾继续 recheck，遇到竞争明确失败。

轻量路由保持，故释放后再次访问原入口会自动构造，不影响别的 Work 的分组展开状态。这里可以复用现有存储层、锁和简单容器，不引入缓存服务或共享跨 Work Reader。

HTTP 套接字设置 10 秒无 I/O 进展超时，断开的浏览器不能无限持有响应发送资源。它不充当 CPU 投影任务的执行期限；后者仍如实占有在途名额，直至返回／异常或显式停止。等待超时只终止该请求，释放所有预留及等待计数；资源繁忙可重试，不能被投影成 Evidence 缺失。

### 不把对象释放说成 RSS 硬限制

两份上下文和每 Work 一次重操作，是首版**可验证的缓存数量与并发上限**。Result 大小、Python 分配器和当前源集解析方式仍会影响峰值；现有单图片 16 MiB 交付限制继续有效。仅释放对象不保证操作系统立刻收回 RSS，最终闲置退出才完整回收进程内存。

验收必须给出上下文实际释放、多 Work 循环不线性持有、等待者有界及进程退出的证据，并记录 RSS/耗时。首版不实现递归对象大小估算器、强制 `malloc_trim`、按 RSS 杀正在读取的进程或另一套模型缓存层。若测量表明两份上下文仍不适用于目标机器，可把内部容量收窄为一份并记录重载代价；不得放宽真实性检查或把“128 MiB 文件预算”声称为物理内存预算。

## 闲置退出、并发与恢复

### 原子地决定停止接入

周期检查器在服务没有有效使用满 259,200 秒、且没有在途内容／交付请求时关闭接入闸门，再退出。检查与 admission 必须共用同步边界：要么新请求先取得 pin 并续期，要么退出先成立，新请求收到明确 `retiring`／连接失败，不允许“接入成功但上下文已销毁”。短 current/health 响应不得续期或阻止已成立的退出。

锁的作用范围固定，不靠一把大锁覆盖全部交付：

1. 父目录级 `lifecycle.lock` 只串行化进程发现、启动发布和文件清理。启动最多 15 秒，health 单次超时不超过 1 秒，所有等待计入交付总期限。每个服务独占其构建目录中的 `process.lock`，从发布连接前持有到退出清理结束。
2. 父进程持 lifecycle 锁启动子进程；子进程非阻塞取得 process 锁并发布 connection，不等待父锁。未退出的实例还占有 process 锁时，不能因为 health 不通启动第二份；已验证正在排空的实例可在期限内等待其退出，**等待前必须释放 lifecycle 锁**，让旧实例完成清理，之后重新加锁探测。无法判定则返回运行时不可用。
3. ensure 完成即释放 lifecycle 锁，随后调用 bind。bind 在服务 admission 锁下核对是否接入并取得在途 pin；昂贵投影及发送响应不持任何跨进程锁或 admission 锁。
4. Work 操作和全局名额的取得在 admission 下有界等待，`Condition.wait` 必须释放该锁。先登记唯一持有人，再释放 admission 进入 Work 锁；结束时先释放 Work 锁，再在 admission 下撤销 pin。任何路径不得持 Work 锁等待 admission，也不得持 admission 等文件锁。
5. 闲置检查先在 admission 下确认条件并关闭闸门，再释放它，停止监听和清理；检查器不得在等待父锁时持有 admission。退出清理最后取得 lifecycle 锁，核对 instance、移除本实例连接信息，再释放 process 锁。`ThreadingHTTPServer.shutdown()` 由不同于 `serve_forever()` 的线程调用，避免 shutdown 自等；不以没有等待者的 sleep 代替真实闸门。

ensure 与 bind 间允许出现“探测时还在、调用时已退出”的竞争，按自动交付节的一次有界重试恢复，**不为消除这个可恢复窗口而把文件锁持有到投影结束**。不要在本地凭不存在的 PID 推断安全，更不能因为 60 秒超时就杀掉另一个仍工作的实例。

`retiring` 是私有 control 503 返回的明确代码，不是新的 Plan 状态；`health` 在排空期间返回真实的 lifecycle。对服务未活着的普通连接错误不虚构退出原因。任何新的 RPC 超时取“剩余交付总期限”和该操作期限的较小值，不以重试重新获得一个 60 秒窗口。

### 退出后的浏览器

- 已加载的分组和图片不清空，不跳转，不把离线误报为新版或 Plan 丢失。
- 可见页的 current 轻量响应附带相对剩余闲置时间，帮助前端停止无意义轮询；它不是业务完成时间，客户端也不能用它覆盖服务端计时。
- 连接已不可用后停止固定 4 秒重试。用户后续尝试新的读取时只做一次节流探测；失败在现有 notice 位置显示“继续查看时，请让 Agent 重新打开此方案。”，不增加常驻管理栏目或倒计时。
- 新读取失败的位置不伪装为“该图片不存在”。只有资源端点明确的图片失败才显示原局部占位；服务离线属于连接问题。恢复仍核对原页面 revision；不能拼接新进程／新版本的内容。
- Agent 使用普通 inspect with view 或正常保存所得新入口即可恢复。浏览器不扫描端口、不执行本地程序、不自动访问另一个 Work，也不引入 service worker 来维持服务。

现有 `<img>` 的 error 回调不能读出 HTTP 状态。首版保留原图像加载方式；失败后先复用页面级单次 current 探测，确认同版本服务仍可用，必要时对同一 asset 作一次有界 fetch 判别响应。连接失败进入离线提示，409 进入过期提示，`view_resource_busy` 保持可重试的临时占位，资源拒绝或图片解码失败才显示“图片无法读取”。不得递归重试整页，也不为了区分状态重新抽帧或读取原图。再次展开该组可重试其临时失败位置，其他已加载组不重建。

### 显式停止与意外退出

`views stop` 保留为诊断／维护动作，目标为调用安装及 data home 的确切服务。明确 stop 先关闭接入闸门，给予现有只读请求最多 5 秒结束，再退出；超时中断的请求必须记为中断，不伪装成功。CLI 不持 lifecycle 锁等待服务退出，避免与服务 finally 清理互锁。它报告实际停止成功，或有界退出验证未完成；不能把端口不响应当退出凭证。

收到 stop、进程异常退出或系统重启后，业务资料不改变。没有独立 supervisor 自动重启；下一次正常 view 交付恢复服务。构造异常或长期无法完成的 I/O 不伪装闲置，保留在途／诊断事实；Agent 必要时可显式 stop 后重新 inspect。停止预览进程不停止 PreCheck、MCP、Agent 或 Apply。

## 运行文件与清理

复用所选 data home 的 `runtime/plan-views/`。每个确切构建仍有自己的瞬态连接信息与有界日志，服务名义下不新增 Dataset 注册表或永久路由文件。连接信息扩展实例、构建、UID、PID 和生命周期协议标识，权限限制为当前用户；PID 只是诊断，不是杀进程或删除目录的唯一依据。

| 内容 | 保留与清理 |
| --- | --- |
| 内存路由、上下文、时间戳 | 无磁盘副本；正常退出全部丢弃 |
| `connection.json` 与本实例发布临时文件 | 由退出实例核对 instance 后移除；不得覆盖／删除后继实例的信息 |
| `process.lock` 与 `lifecycle.lock` | 通过实际文件锁证明所有权；process 文件头保留格式、协议、build、UID 和实例信息，供退出后识别；不删除仍被持有的锁 inode，不根据 mtime 猜进程死亡 |
| 本服务 `host.log` 与一个轮转备份 | 合计约 2 MiB；记录启动、退出原因、聚合回收与错误，不记录逐次轮询、资源 token、控制 secret 或 Plan 正文 |
| 已停止构建的上述诊断 | 7 天后在下一次普通交付中顺带删除；无需用户专门执行清理 |
| Work、Frozen Plan、Result、准备图片、Apply receipt | 完全不属于展示清理范围 |
| 本轮设计参照、评测截图／构建、用户导出的文件 | 不属于产品自动清理范围，不扫描 `.local` 或 fixture 目录 |

清理器与正常启动共用父目录级短锁，并对目标服务的寿命锁作非阻塞核验。只删除已识别协议、当前 UID 所有、位于该 runtime 根内的已知普通文件；拒绝符号链接和未知条目。活动或状态不明的实例跳过，不为了减少目录数量影响另一个构建。

清理在健康服务处理普通 bind 时执行：每次最多检查 16 个旧构建目录，持父锁的目录检查总预算 100 ms；存在更多候选时由该服务记住内存迭代位置，下次 bind 继续。判断 7 天使用最后已知退出／文件更新时间，只作用于证明停止的构建，不作为进程活跃判断。不存在独立永久清理游标或后台清理服务。安全删除空目录需与启动锁协调；无法证明安全时保留小目录／锁文件并记录诊断，不能误删活跃实例。新建 data home 不搬运或清理其他 data home 的记录。

清理为尽力执行：父锁繁忙时跳过，预期的文件访问失败只进入有界诊断，不使已可交付的页面失败；代码不变量或意外异常仍传播。固定父锁文件保留；旧构建的锁文件只有在持有父锁、已安全取得并释放其无人持有的寿命锁且无启动者能介入时才可随空目录移除。子进程退出前记录原因和聚合计数，日志处理器需真正轮转文件；不能继续把 stdout 永久追加到绕过轮转的旧 `host.log` 句柄。

没有再次运行产品时，最多有界的最后诊断可以留在私有运行目录；不承诺“最后一页关闭后立即删除全部文件”。正常退出不保留 HTML 历史，文件保留不进入用户展示或 Agent 的正常 Plan 工作流。

## 诊断入口

使用已有 `mediasense views status --json`，不新建管理 Tool。状态读取不启动服务、不唤回上下文、不续期，至少可检查：

- 已验证的 build、instance、PID、运行／停止／正在排空；无法证明停止时明确 unknown/unreachable，而非将所有连接错误当 stopped；
- 路由数、重上下文数、活动重请求数、等待者数，以及各自上限；
- 距最近实际使用的时间、默认闲置阈值、累计淘汰数；
- 有界最近故障／退出原因及诊断位置，缺证据时为空或 unknown。

上面是诊断语义，不复制 Plan 内容或 URL token。计数来自真实机制，不用 queued／blocked 代表未知失败。使用 `views stop` 后以进程寿命锁释放及相应实例退出核验结果；仅 health 不通不足以报告停止成功。静态 CLI 状态字段的最终名称由现有 CLI 的 JSON 风格确定，含义和验收保持本节约束。

以下诊断原因应可区分（复用原 view problems 形状，无公共枚举扩张）：容量已满 `view_capacity_exceeded`、有界重读取竞争 `view_resource_busy`、服务不可达 `view_service_unavailable`、资源本身不可用 `view_resource_unavailable`、过期 `view_superseded`、意外实现失败 `operation_failed`。HTTP 资产读取遇到 busy 不能返回 evidence_unavailable；正常 idle_timeout 退出只记录为运行时退出原因，不写进 Work 或假造一次 Tool 失败。

Plan 保存成功、view 不可用时，Agent 先认定业务已保存；可 state-only inspect 核对，再用正常 view inspect 恢复。只有运行时异常才需要 status/stop。不得在 Skill 中加入“每次 Plan 前启动／结束后关闭”的固定清单。

## 验收场景

### 只读复核后的两项补修（2026-09-15）
