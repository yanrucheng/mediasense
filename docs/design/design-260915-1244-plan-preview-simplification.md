# Plan 整理结果浏览：设计计划

## 目的与已确认范围

页面让用户先浏览素材的组织安排，再自主展开感兴趣的分组、查看其中的画面。浏览节奏由用户控制，首屏不展开全部分组和图片。

用户已明确保留旧版“完整场景树与代表画面”区域的前端组件：可折叠的分组行、横向图片排列，以及原有的紧凑布局。其他页面区块先移除。标题使用用户视角的名称；本次讨论的“命名”指页面 section 标题，不涉及修改场景、文件夹或文件的实际名称。

2026-09-15，用户实际查看参照稿后表示满意，要求提供提示词交给另一位 Agent 负责。参照稿的视觉、标题和交互方向已确认，接手 Agent 按此基线实施，无需重新发散页面设计。该确认不等于接受样本素材的组织决定或验收正式产品实现。

设计交接时交付的是设计文档与独立 HTML 参照稿；不能把用户对 HTML 的满意解释为对全部非视觉语义变更的接受。2026-09-15 后续实施指令明确要求开发、验证并同步直接受影响的合约与 Skill，本次据此完成页面交付约定的核对与实施，见文末记录；已有 Plan 未修改。

正式页面交付后，用户表示“我觉得挺好的”，随后将讨论转向展示资源负担与自动回收。本页继续拥有已确认的视觉与交互基线；后续[Plan 预览生命周期设计](design-260915-1519-plan-view-lifecycle.md)单独负责自动交付、路由、缓存与进程回收；后续已按用户授权进入实施，状态与证据见该设计的实施记录。

## 界面名称

采用已确认参照稿中的“整理方案”。保留区域只需一个标题，其余栏目本轮不保留。候选命名过程见配对生产记录。

产品界面不使用“树状结构”“目录树”“完整场景树”“视图投影”等描述实现方式的名称。本文为开发交接文档，可以使用组件、布局等工程术语。

## 可直接操作的参照稿

按用户要求，已复制旧 HTML 的保留区域，制作[独立参照稿](../../.local/plan-preview-design/260915-1244/preview.html)。直接打开文件即可浏览，标题为“整理方案”。该稿已获用户认可，是接手开发的视觉和交互参照；后续如需修改已确认的方向，应针对具体差异讨论。

参照稿沿用旧文件的 32 个分组和 198 张内嵌图片，仅呈现标题及折叠分组区域。分组名称、数量、顺序和图片字节保持不变；图片下方两处生产用语改为“记录时间”和“预览关联 N 项素材”，原有时间值及关联数量保留。

这是旧样本数据的交互参照，不是当前 Work 的新候选或已确认计划。文件位于已忽略的本机目录，不将内嵌媒体提交到 Git，也不改写原 HTML 或 fixture。

已在浏览器核对：初始 32 组全部收起；展开单组不会展开其他组；宽窗口为五列图片；同时展开两组后可以独立收起；窄窗口自然单列且无横向溢出。用户对这份参照稿的实际观感已确认；正式实现仍须证明符合该基线。

## 保留组件的具体边界

参照文件是本机的[旧版整理预览](/Users/chengyanru/Downloads/ai-album-hk-representative-v1/mediasense-hk-plan-preview.html)。保留范围从“完整场景树与代表画面”标题及其分组列表开始，到“保留原位置的项目”区块之前结束。文件身份及观察记录见[本计划的生产记录](design-260915-1244-plan-preview-simplification.reasoning.md)。

保留该范围内的呈现结构和样式，以当前 Plan 数据填充。旧文件中的具体分组、数量、媒体和内嵌图片仅是参照数据，不复制为产品数据，也不成为运行依赖。

| 部分 | 设计要求 |
| --- | --- |
| 初始浏览 | 所有分组默认收起；每行显示现有的可读分组路径和素材数量 |
| 按需展开 | 点击一行只展开该组；可以同时展开多个组；收起一组不改变其他组 |
| 组织层次 | 沿用旧版在行标题中表达路径的方式，不为每一级父路径再画一层包围框 |
| 图片布局 | 沿用旧组件的自适应横向网格；较宽窗口一行容纳多张，空间不足再换行 |
| 局部滚动量 | 收起的组不占用画廊高度；展开一组不会把其他组的图片同时铺开 |
| 图片与文字 | 保留图文对应关系、可辨认的文件名和必要信息；内部 Evidence 标识不直接占据图片说明 |
| 窄窗口 | 网格可自然减少列数；允许手机宽度下单列，不把桌面横排机械变成固定宽度溢出 |

旧组件的实现参照是分组容器 details.group、行标题 summary、数量 count 和 gallery 网格。其网格采用自适应列，最小列宽约 210px、间距 12px、图片展示高度 180px；这些是复用起点，验收以原有浏览效果和适配结果为准。

分组顺序、路径名称、成员归属、数量、选定预览及其顺序都来自同一份当前 Plan。前端不重新分类、不改名，也不为了贴近旧文件的画面数量而重新挑选或去重 Evidence。组的素材数量与预览图片张数保持不同含义。

本轮不新增搜索、排序、筛选、轮播、编辑器、成员检查器或证据面板。旧文件中位于保留区域之前的搜索框也不进入这次保留范围。后续增加任何能力，应从新的用户需要另行讨论。

## 页面移除的内容

正常浏览页面仅保留上述区域及其标题。移除旧版的顶部介绍、统计卡片、查找示例、搜索框、独立说明区、保留原位置列表和页脚说明；也移除新版的下列独立区块：

- Work、revision、Result 等内部绑定信息；
- 范围与完整性；
- 工作说明与偏好；
- 其他明确处置；
- 决定说明与适用范围；
- 待安排清单和冻结记录面板。

移除展示不删除对应 Plan 数据，不把这些区块换成默认展开的抽屉、调试面板或另一组卡片。

组件自身的必要状态在发生处表达：尚未保存分组时显示简短空状态；图片无法读取时在该位置保留明确占位；页面版本过期时提示重新读取当前内容。此类状态用于解释当前无法正常浏览的原因，不增加常驻的诊断栏目，不用假图替代失败图片。

## 内容归属与当前合约的衔接提案

页面聚焦分组及画面。生产过程继续保存在已有工作记录中，完整组织决定继续由已有 Candidate／Frozen Plan 承载。

| 信息 | 归属和交付 |
| --- | --- |
| 分组、路径、素材数量及预览 | 页面保留组件，读取同一份已保存 Plan |
| Agent 的工作说明、调查过程、偏好快照、内部引用 | 既有 Work 与 Tool 读取；不作为页面浏览主线 |
| 影响接受决定的命名疑点、例外、限制和未确认事项 | 仍保留在相应的正式决定说明中；最终接受前由 Agent 在对话中向用户交代 |
| 未分组范围、保留原处、排除等处置 | 保留精确数据及 Tool 读取；影响整案接受的部分随同一版本在对话中交代 |
| 最终接受与冻结 | 沿用现有聊天接受和严格版本绑定；页面访问或展开操作不构成接受 |

这采用 reasoning-sidecar 的内容边界，但不新增一套 Plan 运行时 sidecar：既有 Work、Candidate、Frozen Plan 和 Tool 各自保有原来的权威。不能把影响用户判断的事实当作生产过程隐藏或丢弃；简化后的页面也不独自证明用户已经审阅整份 Plan。

设计交接时，[Plan Work 合约的 Continuous page 部分](../spec/contract/plan-work/index.md#continuous-page)要求页面交付其他处置、未安排范围、说明作用域、成员续读等内容。此次实施已按后续授权收窄页面职责，同步这些页面承诺，以及 [Strict revision-bound acceptance and seal](../spec/contract/plan-work/index.md#strict-revision-bound-acceptance-and-seal)中关于审阅交付的表述：

1. 页面承担组织安排的可视化浏览；完整方案审阅由精确版本的页面与同版本对话交代共同完成。
2. 公开 Tool 的完整内容、精确范围和有界续读能力保留。不得因页面简化而截断权威内容、伪造完成或消除例外。
3. 最终接受前，Agent 必须交代未在页面展示但足以改变用户接受决定的事项；如无法完成交代，就不能声称已经完成整案审阅。
4. 已加载页面、续页和图片保持版本一致；新保存使旧确认失效，刷新和浏览本身不创建新版本。

这一衔接依赖后续明确的实施授权，不能仅凭视觉认可推出。开发者不能只删除页面内容后继续宣称符合未经调整的旧页面承诺，也不能为满足旧展示要求把已移除栏目重新塞回页面。

## 实现落点与交接顺序

复用当前只读页面服务和准备图片交付，浏览入口继续由普通 Tool 提供。本轮不以“回到单文件”为目标，也不新建服务、业务模型、组件注册表或独立权威数据。

| 现有位置 | 接手开发时的作用 |
| --- | --- |
| [页面 HTML](../../src/mediasense/_resources/plan-view/index.html) | 收敛页面骨架和已选标题 |
| [页面脚本](../../src/mediasense/_resources/plan-view/app.js) | 将现有分组投影接入旧组件，保留有界读取和版本约束 |
| [页面样式](../../src/mediasense/_resources/plan-view/style.css) | 复用旧组件的折叠行、间距、图文关系与横向网格 |
| [Plan 页面投影](../../src/mediasense/plan/view.py) | 仅在现有展示数据不足时作必要适配，不引入语义判断 |
| [Plan Work 合约](../spec/contract/plan-work/index.md)与[Plan Skill](../../src/mediasense/_resources/skills/mediasense-plan/SKILL.md) | 同步被接受的页面边界、同版本审阅交付及发布副本 |

交接按下列阶段推进：

1. **基线与契约核对**：视觉、标题、保留和移除范围已由参照稿确认。接手 Agent 先读取该 HTML 和当前合约，核对非视觉审阅交付差异；涉及尚未授权的公开语义或权限变化时给出具体修订供审阅，不重复确认已定页面方向，继续推进不受影响的实现。
2. **开发交接**：由用户安排的 Agent 按已定设计同步合约表述、页面和相关 Skill；已有 Plan 数据和冻结语义不因前端改动而重写。
3. **效果复核**：同一份 Plan、相同窗口宽度下对照旧组件，演示初始状态、单组展开、多组展开、收起和窄窗口；先确认体验，再记录实现验收。

用户已经指定旧组件为复用基线，因此不另行设计一套全新视觉语言。发布、安装升级和真实用户 Plan 的修改不属于本次设计交付。

## 验收依据

| 观察场景 | 必须成立 |
| --- | --- |
| 首次打开包含数十分组的页面 | 默认呈现紧凑分组行；没有全量展开的画廊或递归套框 |
| 展开一个有多张预览的组 | 只展开该组；桌面宽度下可见多列图片，图文归属清楚 |
| 同时展开两组再收起一组 | 保持用户选择，其他组不跟随展开、收起或重置 |
| 浏览未展开的其他组 | 不必经过所有组的图片与长篇技术标识 |
| 页面内容核对 | 分组、路径、数量、预览仍属于原 Plan；未通过前端“美化”修改组织含义 |
| 局部图片失败或内容为空 | 组件给出真实的局部说明，不制造空白成功、假图片或默认展开的诊断区 |
| 版本更新或分页续读 | 保留现有过期拒绝、当前入口和有界读取，不拼接不同版本 |
| 请求整案接受 | 影响接受的范围、例外和不确定性已随精确版本交代；没有把看过分组页面等同于接受完整方案 |
| 用户观感复核 | 用户确认保留了旧组件欣赏的浏览节奏、横向排列和展开方式 |

工程检查不能替代最后一项。参照 HTML 的浏览器检查不代表正式页面服务、数据接线或版本约束已验收；静态文档检查也不作为产品验收。

设计定案后，如拟新增栏目、改变默认展开方式、调整分组含义或新增独立展示状态存储，应重新审阅受影响的设计范围。


## 实施与验证（2026-09-15）

用户后续指令明确授权正式开发和验证，并要求同步直接受影响的合约、Skill 和发布副本。本次只更改既有页面资源及其交付说明，没有新增服务、Tool、运行时模型或业务状态。工程自验已完成；交付后用户认可页面观感，见前文反馈。没有发布或升级日常安装。

### 合约差异核对

| 设计差异 | 本次落实 | 不变边界 |
| --- | --- | --- |
| 全内容页面改为分组浏览 | 标题为“整理方案”，仅保留独立折叠行及横向自适应画廊；空状态、失败、过期提示按需出现 | 原有分组、路径、成员、顺序及预览选择不变 |
| 页面删去其他处置、未安排范围和决定说明 | 数据与有界读取仍在原 Tool；完整审阅需同版本对话交代所有足以改变接受决定的信息 | 不把分组浏览等同于整案审阅，不丢弃例外 |
| 移除页面成员／证据面板 | 分组续页保留；现有精确成员和 Evidence 读取继续可用 | 版本绑定、分页真正到末尾、真实失败均保留 |
| 最终接受与冻结 | 合约及 Skill 明确页面加同版本交代后才可请求聊天接受 | 没有修改确认上下文、失效规则、seal 或 Apply 权限 |

同步位置为当前 `plan-work/index.md`、机器定义说明与对应包内 JSON、包内 `mediasense-plan/SKILL.md`。仅机器定义的说明文字变化，请求／响应结构不变。无需新增权限或业务决定；本次没有对真实 Work 发出 update 或 seal。

### 实现

复用 `src/mediasense/_resources/plan-view/` 的三个页面文件和原 PlanView 投影。宽窗口网格最小列宽 210px、间距 12px，图片高 180px；组间距 14px、内边距 15px，沿用参照的颜色、圆角及图文布局。窄窗口自然减少列数。图片沿用当前投影的可读文件名，不填入参照样本的记录时间或关联数量。

图片在首次展开该组时载入；展开多个组或续页不会重建已有组。分页仍绑定初次取得的 Work/revision，过期响应或后台发现新版后不拼接内容。当前入口刷新读取当前版本，精确入口刷新保持原版本约束。图片错误保留原位置及文件名；短暂版本检查失败恢复后移除该提示。

- 源码相关测试 203 项通过。排除已有无关改动的隔离 wheel 中，Plan、合约、CLI 和 Skill 集成测试 212 项通过；artifact-only 分发一致性检查、JS 语法、Ruff 和差异空白检查通过。
